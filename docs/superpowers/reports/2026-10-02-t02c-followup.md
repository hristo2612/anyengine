## Review fixes

1. **Actual requirement sources.** At startup and effective-posture resolution, read `/etc/codex/requirements.toml` and decode the macOS `com.openai.codex` preference `requirements_toml_base64` obtained with `/usr/bin/defaults read`. Files refresh on every resolution; the MDM query cache lasts at most five seconds. Any `permissions.filesystem.deny_read` key restricts every effective thread posture, including existing local/upstream threads and built-in profiles. Invalid TOML/base64/UTF-8, unreadable/non-file/oversized sources and preference-query failures restrict reads. Missing files/preferences are allowed. `smol-toml` is pinned at 1.9.0 so quoted keys, dotted keys and inline tables are parsed rather than approximated. Test-only source overrides are documented. **Cloud requirements are not locally visible and are not handled.** The old wire scan remains a harmless conservative superset, not evidence that Codex 0.159 sends requirement denies.
2. **Unknown callers.** Refuse child control when the caller cannot be identified and any active local or upstream thread is read-restricted. Tests exercise both spawn tools with either ownership type restricted; the same resolver also guards send and bridge exec.
3. **Terminal controls.** Model-authored prompts, rehome text and appended attachment text lose C0 controls except LF/TAB, plus DEL/C1, before paste. ESC is removed, so embedded `ESC[201~` cannot terminate bracketed paste. The existing launch flag and visible leading-slash wrapper remain.
4. **Report correction.** The earlier direct CLI control was not proof of the adapter's operator-input path. The production paste helper already prepends a space to operator slash text, causing Claude 2.1.287 to treat it as prose. This pre-existing limitation remains unchanged and is recorded in both the original report and configuration guide.
5. **Startup race.** The review's auto-mode offer is captured as a screen-text fixture and explicitly declined. Prompt paste, initial Enter, retries and steering recheck screen ownership; unknown dialogs cannot reuse stale composer/footer readiness. SessionStart and timeout no longer permit submission. A known offer interrupting an already pasted prompt is declined and the turn fails safely for retry. Multiline/wrapped prompts remain supported, and steering propagates guard errors to its caller.

The conservative read rule is unchanged: restricted Claude children have no file or shell tools, including bridge exec; unsupported GPT/Grok delegation is refused. Custom-profile/wire restrictions remain sticky once recorded.

## One Claude environment allowlist

PTY, `claude-p`, SDK and Task 16's trampoline all call `claudeEnvironment()`. Inherited keys are `PATH`, `HOME`, `USER`, `LOGNAME`, `SHELL`, `LANG`, `LC_*`, `TMPDIR`, `TERM`, `CLAUDE_CONFIG_DIR`, and `ANYENGINE_*`. Credentials, provider selectors/URLs, managed-settings overrides, proxies and Node TLS/loader variables are excluded. Each launch may then supply its own trusted controls: the trampoline supplies its MCP description-length and timeout limits; the PTY supplies terminal/resume controls and freshly generated hook/proxy settings. There is no second trampoline allowlist.
