## Composer and dialog behavior

Claude **2.1.287** removes `? for shortcuts` after paste; plan, accept-edits and auto mode can omit it even while idle. A collapsed paste can show only `paste again to expand`. The previous footer-dependent implementation was wrong. The new parser identifies the `❯` input inside two column-zero horizontal rules and compares the framed input with the expected prompt (including wrapped/collapsed forms). Mode and status footer contents are not readiness conditions.

Dialogs are recognized by confirmation/cancel hints, numbered choices or selected option rows outside the composer. A stale composer below an old transcript cannot turn pasted consent text into a startup answer. Unknown dialogs remain bounded waits followed by a named error, including the cwd and instruction to run `claude` there once. Steer uses the same diagnostic. Known auto-mode offers are explicitly declined with their **captured** negative label: `No, keep manual mode`, `No, keep plan mode`, or `No, keep accept edits`. No new affirmative answers were added.

`test/fixtures/claude-composer-2.1.287.json` contains **18 real screen captures**: idle/pasted manual, plan, accept-edits and auto; wrapped and collapsed paste; trust, theme/onboarding and new-project-MCP dialogs; and auto-mode offers in manual, plan and accept-edits modes. Production `PtyScreen` decoded the PTY output; only scratch paths were replaced with placeholders. Tests use those screens directly. The fake now emits the same composer framing and mode-dependent footers, removes shortcut hints after paste, and renders collapsed-paste status.

## Local requirements and other sources

Local requirements are now a live overlay, never a persisted thread restriction. An internal symbol records whether an underlying wire restriction existed; request application, posture fields, inheritance and the direct SQLite serializer remove the local overlay before storage. Effective thread/context/child/launch resolution reapplies the current local source. Recovery tests pass actual SQLite round trips after a malformed source recovers, including child/fork/direct-write paths. **Wire restrictions remain sticky.**

| Source | Handling |
| --- | --- |
| `/etc/codex/requirements.toml` | Parse TOML; deny-read keys or unreadable/malformed source restrict reads. |
| MDM `requirements_toml_base64` | Decode and parse; query/decoding failures restrict reads, with a five-second query cache. |
| `LegacyManagedConfigTomlFromFile` (`/etc/codex/managed_config.toml`) | Fail closed on presence, including unreadable contents. |
| `LegacyManagedConfigTomlFromMdm` (`config_toml_base64`) | Fail closed on presence or query failure. |
| `CompositeEnterpriseManaged` / `enterpriseManaged` | Fail closed when `config/read` layer/origin metadata reveals it; the pseudo-path is not read as a local file. |
| `CloudConfigFragment` | Fail closed when its metadata is observed. |

**Unseen cloud requirements remain unsupported.** A requirements-only cloud bundle may have no exposed layer or origin; there is also no such metadata before Codex returns it. The adapter does not claim complete cloud-policy inheritance. A full layers snapshot refreshes the observed managed-source state; partial responses cannot clear it. New legacy-source path overrides keep tests hermetic.
